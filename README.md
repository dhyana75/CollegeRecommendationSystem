# College Recommendation System

A Java Swing desktop application backed by MySQL/JDBC. The existing GUI screens are retained and the data services target the schema from your uploaded SQL script.

## Requirements
- JDK 17 or newer (JDK 21 recommended)
- MySQL Server and MySQL Workbench
- MySQL Connector/J JAR included in `lib/`

## 1. Set up the database
1. Open `sql/final_collegedb_setup.sql` in MySQL Workbench.
2. Run it **once against an empty `collegedb` database**. It creates the tables, trigger, procedures, and the 15 sample records.
3. The bundled setup avoids dropping the whole database. It is not designed to be run repeatedly over already-created tables; back up any data before changing the schema.
4. Verify with `USE collegedb; SHOW TABLES; SELECT * FROM COLLEGES; SELECT * FROM CUTOFFS;`.

The uploaded SQL had one mismatch in its sample data: choice code `628524550F` derives course ID `24550`, but `Computer Engineering` already exists with course ID `24510` and `course_name` is UNIQUE. The bundled trigger reuses the existing course ID for an existing course name so this sample row can be inserted without changing the table schema.

## 2. Configure the Java connection
Open `src/com/college/db/DBConfig.java` and set the values to match your local MySQL account:

- URL: `jdbc:mysql://localhost:3306/collegedb`
- USER: your MySQL username (the current default is `root`)
- PASSWORD: your local MySQL password (the current value is the one already present in the project; change it if it differs from your local password)

Do not share or commit your database password publicly.

## 3. Compile and run on Windows
- Double-click `run.bat`, or run it from Command Prompt in the project directory.
- `run.bat` compiles the source into `out/` and starts `com.college.Main`.
- `compile.bat` uses `compile.ps1` to generate a Java source argument file with forward-slash paths, avoiding the Windows backslash/path error.
- To test the JDBC connection alone, run `com.college.db.DBTest` from your IDE after compiling.

## Schema notes
- The database stores institute code/name and city; it does not contain university, address, or seat-count columns. Those fields are not represented as editable database fields in the GUI.
- Courses are represented by `COURSES` plus the college/course association in `COLLEGE_COURSES`.
- Cutoffs are stored in `CUTOFFS` and classified in `jee_cutoff` or `mht_cet_cutoff`.
- The search screen accepts JEE Main percentile and category code and saves recommendation sessions/results to `RECOMMENDATION_SESSIONS` and `RECOMMENDED_COLLEGES`.
- The supplied sample records use category code `AI`, which the SQL trigger routes to JEE(Main).
- The SQL schema has no persistent bookmarks table; bookmarks remain in memory for the current application session.

## Current limitations
- Institute codes in the supplied sample are numeric; the current GUI's legacy model represents them as integers.
- Course IDs and choice codes for courses manually added through the admin GUI are generated by the application; imported records keep their choice codes from the SQL staging trigger.
- The cutoff admin form uses the latest available cutoff year, CAP round 1, and an unset merit rank because those fields are not currently editable on the GUI.
- Compilation was tested in the build environment. Live MySQL connection and Swing workflow tests still need to be performed on your computer.
